# Relevé MT — المرحلة 7 — مزامنة الهواتف بشكل موثوق

نسخة مطوّرة من تطبيق قراءة عدادات MT مع حساب شهري، حسابات موظفين/مسؤولين، ومزامنة مباشرة عبر Supabase، ومهيأة للتحويل إلى Android APK بواسطة Capacitor.

## ما تم إصلاحه/إضافته في هذه المرحلة

- تم إدخال **قائمة الزبناء الأصلية كاملة (63 زبونًا)** من ملف `ReleveMT_monthly_v2.txt` داخل `src/data/clients.js`.
- عند اختيار شهر جديد، **Index القديم** يُؤخذ من آخر قراءة محفوظة قبل ذلك الشهر.
- حساب الفرق بين Index القديم والجديد.
- تنبيه وتلوين إذا كان الجديد أقل من القديم، مع استثناء Index 14 و15 و16.
- فحص مجموعات Total مع سماح أقصى **10**.
- تحميل القراءات الشهرية بعدد أقل من طلبات الشبكة بدل طلب مستقل لكل Index.
- تحسين الانتقال بين الزبناء حتى لا يختلط الترتيب عند استخدام البحث.
- تحديث مباشر عبر Supabase Realtime.
- Excel حسب الفترة.
- إضافة `index.html` وPWA manifest وتهيئة Capacitor.

## إعداد Supabase

1. نفّذ `supabase/schema_step2.sql` في مشروع Supabase.
2. أنشئ حسابات الموظفين والمسؤول في Authentication.
3. أضف صفوف `profiles` للأشخاص.
4. اربط العقود بالموظفين عبر `employee_clients`.
5. أنشئ `.env` انطلاقًا من `.env.example`:

```env
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

لا تضع `service_role key` داخل التطبيق.

## تشغيل نسخة الويب

```bash
npm install
npm run build
npm run dev
```

## تحويلها إلى Android APK

المشروع مهيأ لـ Capacitor 8.4.2.

```bash
npm install
npx cap add android
npm run build
npx cap sync android
npx cap open android
```

من Android Studio يمكنك إنشاء APK من:

`Build > Generate App Bundles or APKs > Generate APKs`

أو من الطرفية:

```bash
npm run cap:apk
```

## ملاحظة عن هذه البيئة

تم تجهيز المشروع والملفات اللازمة للتحويل إلى Android، لكن بيئة المحادثة الحالية لا تحتوي على Android SDK/Gradle ولا تستطيع تنزيل حزم npm الخاصة بـ Capacitor من السجل الخارجي، لذلك لا أضع APK وهميًا. عند تنفيذ الأوامر على جهاز فيه Node.js + Android Studio/SDK سيتم إنشاء APK حقيقي.

## المرحلة 5 — لوحة المسؤول لتوزيع الزبناء

تمت إضافة قسم **الموظفون والزبناء** داخل لوحة المسؤول:

- عرض جميع حسابات الموظفين الموجودة في `profiles`.
- عرض عدد الزبناء المخصصين لكل موظف.
- اختيار موظف.
- البحث عن الزبون بالاسم أو رقم العقد أو رقم العداد أو القطاع.
- تخصيص/إزالة تخصيص زبون بنقرة واحدة.
- تخصيص أو إزالة تخصيص جميع النتائج الظاهرة دفعة واحدة.
- الحفظ مباشرة في جدول `employee_clients`.
- الموظف يرى فقط العقود المخصصة له في تطبيقه.
- لا يتم وضع `service_role key` داخل التطبيق.

### إنشاء حساب موظف جديد

لأسباب أمنية، إنشاء مستخدم جديد في Supabase Authentication لا يتم من تطبيق الموظف/المسؤول باستعمال مفتاح `service_role`. أنشئ حساب الموظف في Supabase Authentication، ثم أضف له صفًا في `profiles` بالدور `employee`. بعد ذلك سيظهر مباشرة في لوحة المسؤول ويمكن توزيع العقود عليه.


## مزامنة الهاتف مع هاتف المسؤول

المزامنة المباشرة تعتمد على Supabase Realtime. عندما يدخل الموظف Index جديدًا ويحفظه التطبيق، يتم رفع القراءة إلى `meter_readings`، ثم تصل إلى لوحة المسؤول عبر قناة Realtime بدون تحديث يدوي للصفحة. تظهر حالة الاتصال في التطبيقين.

### إعداد المزامنة

1. أنشئ مشروع Supabase.
2. نفّذ كامل ملف `supabase/schema_step2.sql` في SQL Editor. الملف يفعّل Realtime على `meter_readings` و`employee_clients`.
3. أنشئ حسابات الموظفين والمسؤول في Authentication.
4. أضف `profiles` بالأدوار `employee` و`manager`.
5. وزّع العقود على الموظفين في `employee_clients`.
6. أنشئ ملف `.env` محليًا من `.env.example` وضع URL وAnon Key الخاصين بالمشروع.
7. ابنِ التطبيق ثم ثبّت نفس الـAPK على هواتف الموظفين وهاتف المسؤول. جميع الهواتف يجب أن تستخدم نفس مشروع Supabase ونفس بيانات الاتصال.

### النتيجة

- الموظف A يدخل القراءة من هاتفه.
- القراءة تحفظ في Supabase.
- هاتف المسؤول يستقبل التغيير مباشرة ويعرضه في صفحة القراءات.
- إذا انقطع الإنترنت، يظهر ذلك في التطبيق، ويعاد الاتصال بقناة Realtime عند عودة الشبكة.

> مهم: `VITE_SUPABASE_ANON_KEY` يمكن وضعه داخل تطبيق العميل. لا تضع `service_role key` داخل APK.

## المرحلة 7 — تحسين مزامنة الهواتف

تم تحسين المزامنة لتكون أكثر موثوقية عند العمل الميداني:

- الموظف يحفظ القراءة في Supabase، فتظهر في هاتف المسؤول مباشرة عبر Realtime.
- عند انقطاع الإنترنت، تُحفظ القراءة محليًا مؤقتًا داخل الهاتف بدل فقدانها.
- عند عودة الإنترنت، يحاول التطبيق إرسال القراءات المعلقة تلقائيًا ثم يعيد تحميل البيانات.
- زر **مزامنة الآن** موجود في تطبيق الموظف ولوحة المسؤول لإجبار التطبيق على إعادة المزامنة فورًا.
- عند إعادة الاتصال بقناة Realtime، يتم إعادة تحميل قراءات الفترة الحالية للتأكد من عدم وجود تحديثات فاتت أثناء انقطاع الاتصال.
- نفس مشروع Supabase يجب أن يكون مضبوطًا على جميع الهواتف.

### طريقة الاستخدام

1. المسؤول ينشئ حساب الموظف في Supabase Authentication ويضيفه في `profiles` بدور `employee`.
2. المسؤول يخصص له العقود من تبويب **الموظفون والزبناء**.
3. الموظف يفتح تطبيقه، يختار شهر القراءة، ويدخل Index.
4. بعد الحفظ، تظهر القراءة في لوحة المسؤول مباشرة إذا كان الإنترنت متوفرًا.
5. إذا لم يكن الإنترنت متوفرًا، تظهر رسالة بعدد القراءات التي تنتظر الإرسال، وسيتم إرسالها تلقائيًا بعد عودة الشبكة.

> لا يزال `service_role key` ممنوعًا داخل التطبيق. استعمل فقط `VITE_SUPABASE_ANON_KEY`.
